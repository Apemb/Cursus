La page du workflow — de l'historique au hub

On a tranché : cliquer une ligne de workflow ouvre sa page. Dès aujourd'hui elle porte deux onglets vivants — Historique (neuf) et Étapes (l'éditeur existant, replié dans le hub) — plus un bouton Lancer. Le graphe et les déclencheurs viendront après, sans refonte. Voici la trajectoire, pour la valider avant de coder.

Ce qui ne bouge pas d'une étape à l'autre

Une ligne d'historique= un RunSummary. Cliquer rouvre l'écran de run existant en relecture (RunViewModel.Replay) — déjà construit, rien à refaire.
La seule couture CoreProjectHost.RunsOf(workflowId), jumeau testé de LastRunPerWorkflow (filtre ListRuns() sur le workflow). Le reste est présentation (§7.12), non testé.
Les deux listes distinctesla liste des workflows reste l'index au niveau projet (on entre dans un workflow depuis elle) ; la liste des runs vit dans la page du workflow. On ne duplique pas la première dans la seconde.
Aujourd'hui vs demainl'étape 1 construit le module Historique et replie l'éditeur dans l'onglet Étapes (reparentage de présentation, zéro Core neuf au-delà de RunsOf) ; le graphe statique et les déclencheurs (cible acceptée mais reportée, §7.10.6) sont la trajectoire, pas ce jalon.
